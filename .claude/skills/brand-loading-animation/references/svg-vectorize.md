# PNG → 可動畫 SVG（含帶文字的 Logo Lockup）

素材只有 PNG、沒有分層向量檔時，先重建成可動畫的 SVG。重建結果存成一份 JSON，之後所有 demo 和正式版共用。

## PNG → 可動畫 SVG

拿到的素材只有 PNG（無透明背景圖層拆分、無向量檔）時：

1. 用 alpha channel threshold 抓出圖案的不透明區域，再用 connected-component labeling（例如 `scipy.ndimage.label`）把圖案拆成幾個獨立色塊/部件（例如：一個環形 + 幾條色塊，對應 logo 原本設計上就分離的圖形元素）。
2. 對每個色塊分別跑 `potrace` 描邊向量化，產生乾淨的 SVG path。
3. potrace 輸出會帶一個座標轉換矩陣，把每個部件的 path 用該矩陣「烘焙」回統一座標系（例如用 `svgelements` 的 `Path *= Matrix(...)`），這樣才能讓所有部件在同一個 `viewBox` 下正確疊合、且後續動畫變形（旋轉、位移）不會跑掉。
4. 完成後務必用 cairosvg 等工具重新 render 一次，跟原始 PNG 做像素比對，確認重建後的 SVG 跟原圖視覺上一致，不要憑肉眼掃過就假設沒問題。
5. 把每個部件的最終 path `d` 字串存成一份 JSON（例如 `paths_baked.json`），作為後續所有 demo/正式版共用的唯一資料來源，不要每個 demo 重新向量化一次。

## 帶文字的 Logo Lockup（例如「品牌名 中文＋英文」橫式組合）

如果 logo 素材是「圖形標誌＋品牌文字」的橫式組合（lockup），使用者通常會先讓你試著用網頁字型（Google Fonts／系統字型）重建文字，但**這是預設會被打槍的做法**，除非使用者明確說可以用替代字型。實際發生過的回饋原文：「字體現在錯的，應該是跟logo圖片一模一樣」「可不可以就看成是『圖片』不是文字呢？不確定你再重新理解時會不會以重構文字來設計」。

**正確做法：把文字部分當成圖形素材，走跟 logo 圖案完全相同的向量化流程，不要用任何網頁字型重新排版文字。**

1. 沿用「PNG → 可動畫 SVG」的 alpha threshold + potrace 流程，分別對圖形標誌區塊、標題文字區塊、副標文字區塊各自裁切、二值化、跑 potrace。
2. **文字要拆到「每個字/字母各自獨立可動畫」的顆粒度**，不能整段文字只當一張圖：potrace 描邊完一段文字後會產出很多零散的 path 分量（部首、字母的筆畫可能是分開的封閉路徑），要用「依 x 座標排序、算相鄰分量間距、在最大的 N-1 個間距處切開」的方式分群（N = 已知的字數），比固定間距門檻可靠——固定門檻遇到筆畫特別密集/特別寬的字（例如中文字）容易誤判、字數對不上。分群完務必用色塊區分渲染一次，肉眼核對字數跟原圖是否一致，不要只信任程式輸出。
3. 每個字/字母的最終 path 一樣要用 potrace 自己宣告的座標轉換矩陣「烘焙」回統一座標系（見「PNG → 可動畫 SVG」），存成一份共用 JSON（例如 `wordmark_build_data.json`），包含圖形標誌、標題、副標三組 path 資料與各自的 viewBox 尺寸，作為後續組裝任何動畫版本的唯一資料來源。
4. **重要陷阱**：如果改用 `svgelements` 的 `SVG.parse()` + `svg.elements()` 去自動解析 potrace 輸出、取得已經套用好 group transform 的座標，算出來的座標會是錯的（實測會被額外乘上一個 pt→px 的 4/3 倍縮放，導致整體範圍被壓縮成看起來合理但實際錯誤的數字）。要改成用正規表示式直接抓 SVG 檔案裡原始的 `d="..."` 字串，自己手動套用 potrace 宣告在最外層 `<g transform="...">` 的矩陣，不要依賴 `svgelements` 的自動座標解析。用 cairosvg 把 potrace 原始輸出重新 render 一次、跟手動烘焙後的座標比對，確認數字一致再繼續。
5. 動畫呈現上如果使用者反饋「文字動畫太單調、想要更有網頁設計感」，不要做成整段文字一次淡入/位移這種單一動作；改成每個字/字母各自帶不同的 `--delay`，做出上升＋縮放＋短暫變色閃光的層疊進場（跟圖形標誌部件同一套 CSS 自訂屬性技法），視覺上才會有「逐字組裝」的層次感，而不是兩行文字整體淡入淡出。
