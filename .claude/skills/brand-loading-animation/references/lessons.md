# 踩坑教訓（morcept-harness 五欄格式）

每一條都是實際發生過的問題。遇到類似狀況先查這裡。

## 教訓表

| 情境 | 錯誤 | 根因 | 修法 | 升級 |
|---|---|---|---|---|
| 用短碼把動畫程式碼寫進 Enfold 頁面內容 | `[av_codeblock]` 內容前台顯示成字面上的 `[avia_codeblock_placeholder uid="0"]`，程式碼沒執行 | `av_codeblock` 依賴視覺化編輯器同步的 postmeta，短碼本身內容不是唯一依據 | 改用 HFCM 外掛注入，不要用 `av_codeblock` 塞任意原始碼 | 不需要 |
| 把原始 `<style>/<script>` 直接寫進 `post_content` | CSS 在瀏覽器裡「看起來貼上去了」但完全沒生效，畫面呈靜態 | WordPress/Enfold 的 wpautop 類過濾器在 `<style>` 標籤中間插入了 `<p>`，把 CSS 腰斬 | 改用 HFCM，繞過內容過濾器；驗證時用 CSSOM／`getComputedStyle` 而非肉眼看畫面 | 不需要 |
| HFCM「指定頁面」的頁面清單輸入框打字選頁面 | 畫面上選了頁面、存檔後範圍卻沒生效 | 該輸入框只是外觀上的 autocomplete，沒有 `name` 屬性、沒連動到真正送出的 `<select>` | 直接用 JS 對真正的 `<select name="data[s_pages][]">` 建立/選取 `<option>` 並 dispatch `change`，存檔後讀 `selectedOptions` 驗證 | 不需要 |
| 單頁 demo 轉全站正式版時只顧著改後端邏輯 | 全站每頁底部冒出測試用「重播動畫」按鈕跟內部備註文字 | 忘記正式版必須拿掉 demo 專用的 UI 區塊，以為「範圍」是唯一要改的欄位 | 三處一起改：拿掉測試 UI／觸發時機改真實載入偵測／CSS-JS 命名空間跟頁面 ID 脫鉤，缺一不可 | 不需要 |
| 瀏覽器自動化操作 WordPress 後台表單欄位（下拉選單）時 | 部分「改表單欄位值」的自動化操作被 Claude Code 的權限分類器擋下，任務卡住 | 環境對「自動改動線上網站後台設定」這類操作有安全門檻，不一定每次都放行 | 這類欄位改動（套用範圍、插入位置）可以請使用者自己在後台手動點選 1-2 個下拉選單完成，比一直嘗試自動化更快；改完後用唯讀的 JS 檢查（讀取前台 DOM）驗證結果即可，不需要靠自動化寫入 | 不需要 |
| 帶文字 logo lockup，一開始用網頁字型（Google Fonts）重建文字 | 使用者反饋「字體現在錯的，應該是跟logo圖片一模一樣」，網頁字型跟原始商標字體外觀不同 | 誤以為「重建文字內容」等於「用相近字型重新排版」，但客戶要的是視覺上跟原圖分毫不差 | 把文字部分當圖形素材，走 potrace 向量化流程逐字重建，不用任何網頁字型；向量化完用色塊渲染核對字數，並用 cairosvg 跟原圖比對 | 不需要 |
| 文字動畫第一版做成兩行整體淡入 | 使用者反饋「文字的動畫有點偏單調，可以再多一點網頁設計的感覺嗎」 | 把「有文字內容」跟「有設計感的進場動畫」混為一談，兩行文字當一個整體處理，沒有拆到字/字母顆粒度做層疊動畫 | 拆到每個字/字母各自帶獨立 `--delay` 做上升＋縮放＋變色閃光的層疊進場，跟圖形標誌部件共用同一套技法 | 不需要 |
| 用 `.lpwm-is-settled` 跟 `.lpwm-is-playing` 兩條選擇器同時設定 `animation` 屬性在同一元素上 | 引導線（guide）動畫進場後應該淡出卻卡住不消失，畫面停留一條藍色十字線 | 兩條選擇器 specificity 相同，CSS cascade 規則下「後宣告的規則獲勝」，若淡出規則寫在進場規則「之前」，兩個 class 同時存在時進場規則反而繼續生效 | 把淡出（`is-settled`）規則的宣告順序移到進場（`is-playing`）規則「之後」；用 Playwright 截圖比對修正前後畫面確認 | 不需要 |
| 客戶網站沒裝 HFCM，預設用 Enfold skill 的流程去找 HFCM 選單 | 後台完全找不到 HFCM 相關選單，一開始誤判成外掛沒裝好 | 沒有先確認這個網站的建站方式是 Enfold+HFCM 還是 Elementor Pro，兩者程式碼注入的介面完全不同 | 先查外掛清單／後台選單判斷是哪一種站，Elementor Pro 站改用「Elementor → 範本 → Custom Elements → Code」（`post_type=elementor_snippet`），操作邏輯跟 HFCM 對應但介面不同 | 不需要 |
| WPML 多語言網站（不同語言掛不同網域）要求 loading page 只在其中一個語言出現 | 把 Elementor Conditions 設成「指定頁面＝該語言首頁」，結果兩個語言的首頁都出現；改成指定另一個語言的首頁 ID，還是兩個語言都出現 | WPML 對 Elementor 顯示條件做了跨語言翻譯同步，鎖定任一語言版本的頁面 ID，WPML 都會自動套用到它在其他語言的翻譯版本，且這個同步是雙向對稱、Elementor Conditions UI 完全沒有「語言」篩選維度可以繞開 | 放棄用頁面 ID 當條件，改成程式碼最前面加網域判斷（`location.hostname` 比對），不符合目標網域就 `overlay.remove(); return;`；改完務必兩個語言版本都重新用 JS 唯讀檢查一次，不能只測一邊 | 不需要 |
