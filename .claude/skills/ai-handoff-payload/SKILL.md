# AI 複製貼上交接設計（不吃 API 的整合方式）

## 什麼時候用這個 skill
使用者想把工具收集到的資訊（標記、回饋、討論紀錄……）轉交給 AI 處理，但不想開發 API 整合（不用金鑰、不用後端、不綁定特定 AI 平台），只想讓使用者「複製、貼上」就完成交接。

## 做法：剪貼簿 + 開新分頁

```js
navigator.clipboard.writeText(payload).then(function () {
  toast('已複製，貼上即可');
  window.open(aiUrl, '_blank');   // aiUrl 例如 https://claude.ai/new、https://chatgpt.com/、https://gemini.google.com/
});
```

好處：
- 不用維護 API 金鑰與費用，也不會因為 API 政策變動而壞掉。
- 使用者用自己已經訂閱的帳號、自己的對話紀錄，工具本身完全不接觸實際對話內容，沒有資料外流疑慮。
- 支援多個 AI 平台只是加一筆設定的事，不用個別接 SDK：
  ```js
  var AI_OPTIONS = [
    { key: 'claude', label: 'Claude', url: 'https://claude.ai/new' },
    { key: 'chatgpt', label: 'ChatGPT', url: 'https://chatgpt.com/' },
    { key: 'gemini', label: 'Gemini', url: 'https://gemini.google.com/' }
  ];
  ```

## Payload 設計原則：讓 AI 看一次就會動

複製的內容建議是「人類可讀條列文字」＋「結尾一段完整 JSON」的組合：
- **條列文字**：讓 AI（跟事後回頭看的人）快速理解每一點在講什麼，用編號、粗體重點、少量 emoji 分類都可以。
- **結尾 JSON**：保留完整結構化資料（唯一識別碼、原始內容片段、座標、規則設定），給 AI 精準處理，也方便之後程式化解析。

```
【工具名稱】網站「example.com」共 3 筆標記。請直接根據以下每一點，產出 XXX（不需要先確認）：

1. ...條列描述...
2. ...
3. ...

詳細資料：
```json
{ "tool": "...", "items": [...] }
```
```

**最關鍵的一句話，要放在開頭**：明確講清楚「你要 AI 做什麼、做到什麼程度、要不要等確認」。例如：「請直接產出完整PPT並提供可下載檔案——不需要先跟我確認或等我回覆，第一步就直接做出完整成果。」

這句話沒講清楚，AI 很容易只做一半、停下來反問使用者要不要繼續，使用者就得再貼一次指令才能拿到最終結果——如果目標就是「一次到位」，開頭這句指令不能省。

## 何時反而要「分兩步」
不是所有情境都適合一次到位。如果任務本身需要先讓 AI 給出分析／建議，使用者確認方向後再進入下一步產出（例如先討論修改方向，確認沒問題才真的動工），可以刻意保留兩段式：第一段只給資料＋要求先出建議，第二段再用另一則訊息明確要求「根據剛才的討論，產出最終成果」。要不要一次到位，取決於使用者想不想要中間有確認點，不是預設都要省略。

## 常見坑
- `navigator.clipboard.writeText()` 在非 HTTPS（或某些沙盒）環境下可能被瀏覽器擋掉，記得包 `.then()/.catch()` 給使用者明確的失敗提示，而不是靜默失敗。
- `window.open()` 在某些瀏覽器的彈窗攔截設定下可能被擋，最好緊接在使用者的點擊事件（click handler）裡同步呼叫，不要包在 `setTimeout` 或非同步流程太深的地方，否則會被判定為非使用者主動觸發而遭攔截。
- 品牌規範／格式要求這類「每次都要附上」的固定資訊，建議存在 localStorage，複製時自動帶入，不要每次要求使用者重新輸入。
